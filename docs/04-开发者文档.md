## 2. 架构与数据流

```
Views（视图） ── 调用 ──▶ dataStore（Pinia）
                              │ 读：data（响应式）
                              ▼
                          services/dataService
                    ├── githubService（云端读写）
                    └── localCache（本地缓存）
```

- **数据一致性**：所有写操作统一走 `dataStore.addItem / updateItem / removeItem / replaceAll`，内部调用 `markDirty()` 触发 debounce 保存，避免散落直接写文件。
- **批量提交**：`scheduleSave` 在 1.2s 内合并多次变更，只发一次 PUT（规避 GitHub API 限流）。
- **冲突合并**：PUT 遇 409 时 `mergeData` 按 id 合并（本地优先、远端补齐），随后重推。
- **离线优先**：写入前先落 localStorage；加载时远端优先、离线回退缓存。

### 替换数据后端（如接入 Supabase）
只需在 `src/services/` 新增一个 `supabaseService.js`，实现 `readData / writeData / verify / isConfigured`，并在 `dataService.js` 中切换数据源即可。业务层（store/views）零改动。

## 4. 部署到 GitHub Pages

### 4.1 准备
1. 准备一个 GitHub 仓库（可同时存源码与数据），如 `qingyunzhi`
2. 生成 Personal Access Token（`repo` 权限）
3. 创建数据文件 `data/user-data.json`（运行 `npm run seed` 生成，或由应用首次自动创建）

### 4.2 本地验证
```powershell
npm install
npm run dev        # 打开 http://localhost:5173
npm test           # 跑单元测试
npm run build      # 产物在 dist/
```

### 4.3 部署（推荐方案 A：同仓双分支）
1. main 分支：源码 + `data/`
2. gh-pages 分支：`dist/` 构建产物（`npm run deploy` 自动完成）

```powershell
# 先推送源码与数据到 main
git init && git add -A && git commit -m "init" 
git remote add origin <你的仓库地址>
git push -u origin main

# 部署静态站到 gh-pages 分支
$env:GHP_REPO = "<你的仓库地址>"
$env:GHP_BASE = "/"           # 子路径部署时填 "/仓库名/"，根域名留空
npm run deploy
```

3. 在 GitHub 仓库 Settings → Pages → 选择 `gh-pages` 分支 `/root` → 保存
4. 等待片刻即可访问 `https://<用户名>.github.io/<仓库名>/`

### 4.4 部署方案 B：源码与数据分离
- 前端仓库（含 dist）→ Pages 部署
- 独立数据仓库 → 应用设置中填写该数据仓库 owner/repo

### 4.5 PWA 安装
- 手机浏览器打开站点 → 菜单「添加到主屏幕」；桌面 Chrome → 地址栏安装图标
- 离线可查看缓存数据，联网自动同步

## 6. 扩展点
- **云数据库**：替换 `services/dataService.js` 数据源
- **邮件提醒**：在 `utils/reminders.js` 增加邮件渠道
- **图表**：在 `components/charts/BaseChart.vue` 按需注册更多 ECharts 模块
- **自定义页面**：在 `router/index.js` 增加路由 + `views/` 新增视图
- **多用户**：数据结构预留 `user` 对象，可在数据层扩展用户维度

## 7. 已知限制与注意事项
- localStorage 容量约 5MB，长期大量消费记录建议定期导出备份
- GitHub API 未认证 60 次/小时、带 PAT 5000 次/小时；应用已用 debounce 合并写请求规避
- hash 路由适配任意静态托管，无需服务器重写
